## 4. What was connected, and how

`backend/modules/ecosystem-bond.js` is an adapter on the existing kernel.

- `buildMap()` writes the inventory fields requested for each file: `name`, `type`, `path`, `entrypoint`, `dependencies`, `dependents`, `status`, `health_check`, `capabilities`, `inputs`, `outputs`.
- `envelope()` is the task contract: `id`, `type`, `payload`, `priority`, `deadline`, `parent_task`, `expected_schema`, `permissions`, `cost_budget`.
- `dispatch(task, handlers)` checks the kill switch, refuses spend types without a matching permission, queues when no handler is registered, validates the result against `expected_schema` (a map of key to `typeof` string), retries up to 3 times, and on `error.code === 'provider_down'` calls `type + ':fallback'`.
- `attach(kernel)` calls `kernel.register('ecosystem-bond', ...)`. The test process did this. The already-running backend did not, because it was not restarted.
- `GET /api/ecosystem-map` and `GET /.well-known/ecosystem-map.json` were added on the backend app. They return `summary()` only: counts, orchestrator id, kill-switch flag, queue depth, and the last 20 audit rows. They do not return module source or secrets.

Orphans were not mass-required. Doing that would execute them.

## 10. Remaining risks

- Status `active` overstates runtime. 490 files are reachable. This run executed the bond, census `getStatus`, `usi-memory`, and IAK `register` / `getStatus`.
- Shim detection is textual (`module.exports = require(`). It counted 197 files, including pool workers and some real modules that re-export.
- `health_check` is a regex. 386 files show none. `healthOf()` does not load them.
- Audit history and the task queue live in memory (ring of 200). A process restart drops them. They are not the tenant queue and they are not SQLite.
- The circuit opens inside a single `dispatch` once three failures land within five minutes. There is no separate restart of a child process.
- `propose()` never writes source, never auto-approves, and never deploys. The requested auto-approve path for safe config changes was not built. A file-writing auto-apply would fight `DISABLE_SELF_MUTATION`.
- `AUTONOMY_KILL_SWITCH=1` and `UNICORN_AUTONOMY=off` gate `dispatch` only. They do not stop the running kernel, ZACC, or the social viralizer. The existing global gate for source mutation remains `DISABLE_SELF_MUTATION=1`.
- `/.well-known/ecosystem-map.json` is registered on the backend app. If nginx sends `/.well-known/` to the site process, that alias will not hit this route until the site or nginx forwards it. `/api/ecosystem-map` follows the existing `/api` proxy.
- Requiring IAK from a test dirties `UNICORN_FINAL/data/**`. Those files must stay unstaged.
- Two `ab-test-engine` files can be confused. Only the root one is on the entry graph.
